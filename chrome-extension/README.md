# SignalScope · LinkedIn 研究台

此扩展只在用户点击后作用于当前 LinkedIn 公司 Posts 标签页。它只申请：

- `activeTab`：临时访问用户主动选择的当前标签页；
- `scripting`：将本地采集逻辑注入当前标签页。

它不申请 Cookie、浏览历史、账号、密码或网站全局访问权限，不自动登录，也不执行点赞、评论、关注、转发或发帖。扩展的本地后台服务只负责保存文件、断点和累计合并，不发送网络请求。

## 安装

1. Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目中的 `chrome-extension` 文件夹。
5. 可在扩展菜单中将 “SignalScope · LinkedIn 研究台” 固定到工具栏。

## 使用

1. 手动打开并确认可以正常查看 LinkedIn 公司 Posts 页面。
2. 点击工具栏中的扩展按钮。
3. 首次使用可点击“选择文件夹”，选择一个长期保存采集结果的本地目录。Chrome 保留授权后，新扫描结果会直接写入该目录；授权不可用时自动退回系统下载目录。
4. 首次选择“完整采集”；后续可选择研究台导出的累计历史 JSON，再开始增量采集。
5. 选择目标数量（30/50/100篇）和采集节奏：快速模式每轮等待2—3秒，稳定模式每轮等待3—5秒并允许更多次慢加载重试。
6. “查找最早帖子”会持续向下扫描到历史底部，并在 JSON 的 `metadata.oldest_post` 中记录最早帖子；账号历史较长时可能耗时较久。
7. “从当前位置向上扫描”适合先手动滑到某个历史位置，再点击按钮向页面顶部回扫。到达顶部前也可随时点击“停止并导出”。
8. LinkedIn 页面右上角显示滚动轮次、本轮新增、当前最早日期和等待次数，可随时点击“停止并导出”。
9. 完成后自动保存 CSV 和 JSON；未设置文件夹或授权失效时，自动使用系统下载目录。

### 日期范围、断点与完整度

- “开始日期”和“结束日期”均可留空。向下扫描越过开始日期后会自动结束，导出时只保留范围内的帖子。
- 长扫描每新增 25 篇会在扩展内部自动保存断点。扫描异常中断或手动停止后，再次打开同一公司页面会出现“继续上次扫描”。
- 完整扫描只有在页面高度稳定、连续位于底部且多轮无新增时才标记为高可信度。JSON 的 `metadata.boundary_confidence` 与 `boundary_evidence` 会保留判断依据。

### 公司档案与累计文件

- 弹窗中的“公司文件简称”会按公司页面保存，例如可将较长的页面标识设为 `midea`。
- 每轮扫描继续生成 `公司-日期.csv/json` 批次文件，同时自动更新 `公司-master.csv/json` 累计文件。
- 累计文件按永久链接优先去重；`master.json` 会记录新增数量、总批次数、最早与最晚日期，以及覆盖区间内没有帖子的月份。

扩展弹窗底部的“打开研究台”会直接打开扩展内置的本地研究页面，可拖入CSV/JSON进行合并、去重和分析。研究台提供公司与内容主题筛选看板、主题人工修正、运营观察、发布节奏、标签表现、日期筛选、当前筛选下载和本地报告，不需要再到Finder中寻找网页文件。

结束面板会明确显示停止原因。如果未达到目标数量，会出现“下载诊断”按钮；诊断 JSON 只包含采集配置、滚动变化、选择器命中数量和错误日志，不包含账号、Cookie或认证信息。

遇到登录、验证码、安全检查或访问限制时会停止。请按 LinkedIn 正常流程手动处理，不要修改扩展绕过限制。
